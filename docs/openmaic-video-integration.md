# OpenMAIC 视频草稿接入说明

## 定位

OpenMAIC 作为独立的“课程草稿与视频渲染服务”运行，本项目仍负责产品、SOP、视频发布和顾客推荐。不要把 OpenMAIC 源码复制到当前 React/Express 工程，也不要让浏览器直接持有 OpenMAIC 的访问码。

当前接入分为两条通道：

- **OpenMAIC 高品质草稿**：服务端读取已审核 SOP，提交受约束的生成提示词，管理员进入 OpenMAIC 逐场景审核，再从 OpenMAIC 导出 MP4。
- **浏览器本地 WebM**：保留原有 Canvas + MediaRecorder 方案，适合快速生成无声字幕草稿和故障兜底。

当前代码不会自动安装、启动或重建 OpenMAIC，也不会修改已有视频数据。OpenMAIC 未配置或不可用时，本地 WebM 通道仍可使用。

## 独立服务配置

1. 按 OpenMAIC 官方文档在独立目录或独立服务器部署，不能占用本项目的 `3000` 端口。本机示例端口为 `3200`。
2. 在 OpenMAIC 侧配置 LLM、TTS 与其可选的 MP4 render-service。模型密钥只保存在 OpenMAIC 服务端。
3. 在本项目 `.env` 增加：

```dotenv
OPENMAIC_BASE_URL=http://127.0.0.1:3200
OPENMAIC_ACCESS_CODE=
OPENMAIC_TIMEOUT_MS=8000
```

4. 重新启动本项目后，管理员的视频工作室会显示 OpenMAIC 的就绪状态。

`OPENMAIC_ACCESS_CODE` 仅在 OpenMAIC 启用了站点访问码时填写。本项目只访问固定的 `OPENMAIC_BASE_URL`；任务查询不接受客户端传入的上游 URL。

## 固化的内容生成提示词

系统会把每条已审核 SOP 转换为如下约束，而不是让模型自由发挥：

```text
角色：严谨、克制的消费电子售后教学设计师。
目标：制作 45–75 秒、16:9、适合手机和电脑观看的中文线性微教程。
结构：问题说明 → 准备 → 分步操作 → 完成确认 → 人工客服。
禁止：测验、PBL、课堂讨论、虚拟老师、数字人、人物对话、夸张转场、科幻 HUD、营销套话。
事实：SOP 是唯一事实来源，不得改变步骤顺序，不得补造按钮、菜单、功能、参数或完成标志。
素材：只使用材料中已有的真实图片、截图和录屏；无真实素材时只用中性步骤卡和抽象示意图。
真实性：禁止生成假的设备界面、按键位置、产品外观、手部操作或品牌标识。
画面：简洁留白、低饱和中性色、少量品牌蓝；每屏一个动作，短字幕，自然中文旁白。
交付：先生成可逐场景审核的草稿，不声称已经实拍。
```

## 高品质成片的必要条件

OpenMAIC 只能改善内容编排、场景节奏、字幕和配音流程，不能凭空知道真实设备长什么样。要避免“AI 味”，每条正式视频还应准备一个经过审核的素材包：

- 对应型号的真实设备正反面照片；
- 与 SOP 步骤一一对应的屏幕截图或录屏；
- 必要的手部操作实拍；
- 品牌标识、安全警告和客服结尾卡；
- 允许商用的旁白音色与背景音乐授权信息。

没有真实素材时，应使用克制的图文示意，不应生成看似真实但错误的设备画面。

## 发布验收

- 型号、菜单名称、按钮位置和步骤顺序与真实设备一致。
- 每个镜头都能追溯到已审核 SOP 或真实素材。
- 配音没有错字、多音字误读、机械停顿或夸张语气。
- 字幕在手机宽度可读，画面没有过密文字和无意义动效。
- 安全警告完整，未解决时明确引导人工客服。
- 管理员完整观看后再导出、上传和发布；不自动发布模型生成结果。

## 后续阶段

当前官方链路是“生成课堂 → 在 OpenMAIC 中审核 → 浏览器构建 Hyperframes ZIP → render-service 渲染 MP4”。在拿到一套通过验收的真实课堂与 MP4 后，再实现自动回传 MP4、任务持久化和素材包管理，避免在尚未确认效果时先改数据库和发布流程。
